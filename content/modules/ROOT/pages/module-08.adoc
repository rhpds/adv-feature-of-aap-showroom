= The new Self-Service Automation Portal (SSAP)

Starting with version 2.6, Ansible Automation Platform includes a brand new https://www.redhat.com/en/technologies/management/ansible/self-service-automation[self-service portal] based on https://www.redhat.com/en/technologies/cloud-computing/developer-hub[Red Hat Developer Hub] / https://backstage.io/[Backstage].
At first only available to run on Red Hat OpenShift, it is available as a Red Hat Enterprise Linux-based appliance, too. 

The General Availability is planned around Summit 2026 time frame.
But since we wanted to give you a sneak peak into it already, we included a lab chapter based on the Developer Preview version.

== The AAP Self-Service Portal

The self-service automation portal makes enterprise automation accessible to users of varying roles and skill levels through a simplified web interface designed for business users, not automation experts.
Instead of requiring users to understand what's going on under the hood, SSAP provides a streamlined "point-and-click" experience.

Self-service automation portal uses your existing Ansible Automation Platform setup: it uses the same logins, same security controls, and the same automation logic.

== Preparing AAP

Using the SSAP RHEL appliance, administrators will have to configure it and set up tokens and OAuth in Ansible Automation Platform.
Most of this work has been done for you in this lab, only a few steps are required.
First check that the OAuth application has been configured, this is needed because SSAP uses AAP for authentication.

Access your AAP UI using the Showroom tab or by opening it in a browser tab {controller_url}[window=blank]. Login as user **lab-user** with the password **{controller_password}**. From there:

** Go to menu:Access Management[OAuth Applications]
** Open the OAuth application called `Selfservice-*****`
** It should resemble this:

image::oauth-app.png[800,600,link=self,window=blank]

You'll need to create a team called `aap-admins` belonging to the `Default` organization.

. Go to menu:Access Management[Teams]
. Press the blue button: **Create team**
. Enter:
** **Name:** aap-admins
** **Organization:** Default
. Press the blue button: **Create team**

We could create and add users to this new team but {controller_username} as system administrator is already implicitly member of the team (have a look at menu:Access Management[Users > {controller_username} > Teams]).

== Configuring and Accessing SSAP

In the next step, from a terminal as user `lab-user` access the SSAP appliance:

----
ssh ssap
----

** The SSAP appliance is configured using a text-based user interface
** The configuration has already been created and just needs to be activated using the config tool
** Run:
+
[source,shell]
----
sudo portal-setup -c /tmp/portal.env -y
----

Configuring the Portal will take a couple of minutes.
When you are finally greeted with this screen, your Self-Service Portal is ready to go:

image::ssp-ready.png[800,600,link=self,window=blank]

Access the SSP UI:

** Go to {ssap_url}[window=blank], you will be asked to sign in using Ansible Automation Platform
** Click the button: **Sign In**
** You will be directed to AAP, log in as usual if you're not already (user `lab-user`, password `{controller_password}`)
** Click: **Authorize** for Read and Write scope access

You will be greeted by the shiny new SSP Portal! Since you are an admin user, you will see all **Job Templates** configured, but because you are not _the_ `admin` user, you can't do anything with it.
Let's correct this!

== Role Based Access Control

In a real world, you would give mostly others access to the portal.
For sake of simplicity, we will give ourselves access rights to the templates, and the right to synchronize with AAP.

. Select the lower left entry menu:Administration[RBAC].
. Click in the upper right corner **Create** to... create a new role
. Enter the **Name**: ssap_operators and click **Next**
. Select the `AAP Administrators` (you're one of them) and click btn:[Next]
. Select the `Catalog` and `Scaffolder` plugins, and select all permissions under each plugin.
  The result should look as follows.
  When done, press **Next**.
+
image::ssap_permissions.png[link=self,window=blank]

. Finally, press **Create**.

Now, going back to the menu:Templates[] menu, you'll see that you can:

* Sync the templates to get modified and new ones from AAP
* Start the templates already available _if_ your user has this right in AAP as well

== Self-Service Portal synchronization with AAP

"No description available" as template description isn't a great fit so let's fix this:

. Go to AAP, login if necessary
. Select menu:Automation Execution[Templates]
. Edit the `Demo Job Template`
. Enter a menu:Description[] like 'Say hello to the world'
. Press **Save job template**
. Go back to the portal
. Click on [.underline]#Sync now# in the upper left corner
. Selecting the **Job templates** is sufficient, then press **Ok**
. Refresh the browser page

You should now see your new fancy description.

== Execute a Job Template

Now that you know what the job template is supposed to do, you can use it.
As it's the purpose of the portal, it's super simple to do:

. Click **Start**.
. While the job runs, you can **Cancel** it.
. You can also use **Show Logs** to get a simplified version of the job log you know from AAP.
. And once the job is finished, you can restart it with **Start Over**.

== Custom Templates

But the main power of SSAP does come from the ability to use Custom dynamic templates. Custom Templates are templates that are stored in a Git repository and are imported into the Self-Service portal by an administrator. They are used to create new sophisticated, enterprise-ready templates that provide more advanced options than what surveys can offer.

=== Import a Custom Template

Let´s go ahead and import a custom dynamic template.

. Open the SSAP web UI
. In the top right corner, click on btn:[Add Template].

You will be prompted to **Select URL**. This will upload the custom dynamic template from a URL.

Copy and paste the following URL into the Select URL field.

[source,shell,role=execute]
----
https://raw.githubusercontent.com/ansible-labs-crew/customtemplates/refs/heads/main/rhel_dynamic.yml
----

. Select Analyze to analyze the custom dynamic template.
. You will see the Review details.
. Click on Import to import the custom dynamic template.

image::add-ssap-template.png[link=self,window=blank]

You will now see the custom dynamic template in the Templates list with a title of "Manage RHEL Time Servers"

image::ssap-show-custtemp.png[link=self,window=blank]

Our custom template is backed by a Job Template in Ansible Automation Platform, of course. If you look at the URL of the https://raw.githubusercontent.com/ansible-labs-crew/customtemplates/refs/heads/main/rhel_dynamic.yml[yaml template you imported^] you will see the job template it is launching. In that yaml template there’s a section that looks like this:

[source,yaml]
----
    - id: launch-job
      name: Update Time Servers
      action: rhaap:launch-job-template
      input:
        token: ${{ parameters.token }}
        values:
          template: RHEL / Update RHEL Time Servers
          inventory: ${{ parameters.inventory }}
----

So the custom template `Manage RHEL Time Servers` is launching the job template `RHEL / Update RHEL Time Servers` in AAP. However the user will see many more options to choose from when they launch the custom template!

TIP: BTW the job template `RHEL / Update RHEL Time Servers` is snake-oil, i.e. not doing anything but assisting to show the beauty of custom templates. You could of course configure RBAC in a way that a user would only see the custom template and not the job template in SSAP!

=== Launch the Custom Dynamic Template

Time to have a look...

. Launch the custom template by clicking on the btn:[Start] button.
. Examine the options available to the user.
. Enable the **Show Advanced Options?** checkbox. Notice this provides many more options to the user.
. Select the options you like. Then advance using btn:[Next] to the last step and click on btn:[Create] to run the custom dynamic template automation job.

**As you can see, custom dynamic templates provide a lot of flexibility to the user.**
